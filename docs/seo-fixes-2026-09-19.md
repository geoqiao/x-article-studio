# Website fixes — September 19, 2026

Status: implementation and local verification complete; production release results are recorded below after deployment.

## Changes

- `index.html` contains a visible product H1, explanation, workflow and links independently of the React editor. The website keeps a usable editor in the viewport and the standalone HTML retains its original app layout.
- The three public pages have distinct descriptions, final canonical URLs, Open Graph and Twitter card metadata. The homepage describes the actual application with `SoftwareApplication` JSON-LD, without ratings. Sitemap modification dates reflect this content change. `public/og/article-studio.png` is a verified 1200×630 PNG with editable SVG source.
- The connection dialog and support page now link to the published Chrome companion. The unpacked build remains a secondary development option. Format limitations and the requirement for an X account with Articles access are explicit.
- The privacy page distinguishes browser-local articles, the companion's confirmed upload to X, VibeCafé website visit statistics, and Cloudflare hosting/performance measurements. The Chrome Web Store description source was corrected as well; the external store listing still requires its separate metadata update.
- The build injects a local, reviewed telemetry client. It retains the public VibeCafé v1 page-view contract and visitor storage key, runs only on the exact production origin, honors DNT/GPC before storage/network access, omits cookies/referrer and never includes article data. It sends one event per HTML page load without retrying or claiming ingestion success.
- `wrangler.www.jsonc` defines a separate, minimal Worker that redirects `www.md2xarticle.com` to the fixed HTTPS apex with 308, preserving path/query. The editor remains a static asset deployment. The redirect uses the main project's September 15 compatibility date, supported by the installed local runtime.

## Evidence and verification

All web evidence was accessed September 19, 2026:

- Before the changes, the live homepage had only an empty React root. The public [Chrome Web Store listing](https://chromewebstore.google.com/detail/ojpjldmiiibgjnbjfiacaoenfgpdhbbh) was available with version 0.1.0 and update date September 17.
- [VibeCafé's public client](https://vibecafe.ai/telemetry/v1.js) was inspected to verify the event contract. An actual production browser visit reproduced the missing `Access-Control-Allow-Origin` error on POST even though OPTIONS advertised the correct origin. The client never reads the response; a simple `no-cors` request is therefore appropriate for this one-way event. No proxy or server-side forwarding was introduced. Server-side acceptance/counting cannot be inferred from an opaque response.
- A separate Cloudflare redirect Worker is necessary because [Workers static asset `_redirects`](https://developers.cloudflare.com/workers/static-assets/redirects/) does not support domain-level matching. [Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/) provide the hostname and managed TLS certificate.
- `pnpm test`: 59 tests in 7 files passed, including 12 privacy/redirect boundary cases. `pnpm check` and `pnpm build:production` passed. `pnpm build:html` generated the standalone bundle.
- The existing `tests/browser-smoke.js` passed 14 workflow groups in isolated Chrome. One assertion was updated for the new primary Chrome Web Store link. This covers actual rich clipboard copying, image preparation/replacement, native/PNG tables, Mermaid, imports, persistence, errors and mobile tabs.
- The existing `tests/browser-bridge-smoke.js` passed with the real unpacked extension in an isolated Chromium profile: two prepared assets, extension-owned review, repeated-stage reuse, missing-X preflight and discard. No requests reached X.
- In a JavaScript-disabled context, the product H1, workflow and guide link were visible. `/`, `/support` and `/privacy` returned 200 with expected canonicals/descriptions/cards. The `.html` aliases redirected in the local Cloudflare runtime.
- Desktop/mobile checks found no horizontal overflow at 1440×1000, 390×844 or 360×732. The Markdown input started at approximately 294, 378 and 395 pixels respectively, with at least 304 pixels of editing height.
- A production-origin browser fixture used local build assets and a headerless 204 telemetry response. Exactly one minimal event was sent with `no-cors`, no cookies/referrer and no browser CORS error. This fixture did not contact the real telemetry service.
- The redirect Worker passed a Wrangler dry run, unit cases for encoded paths, ports, query strings and fixed-destination safety, and a local HTTP 308 check retaining the complete query string.
